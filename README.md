# PRAMAN AI

PRAMAN AI is an AI-assisted Legal Metrology inspection platform engineered to streamline packaged commodity compliance verification under Legal Metrology packaged commodity rules. The platform integrates multi-panel package and product image capture, optical character recognition (OCR) and text detection, declaration extraction and interactive field review, deterministic, configurable, and versioned compliance rules, visual and image-quality diagnostics, evidence-backed findings and inspection reports, an inspector review workflow, statutory notice and memo drafting with mandatory human officer review, inspection history and analytics, a product master catalog, a consumer transparency scan mode, an evidence-grounded contextual inspection assistant, and authentication, role-based access control (RBAC), and officer identity tracking.

## Core Architecture Principles

- **Compliance Determinism**: LLM and AI assistance does **not** independently determine statutory compliance. Automated compliance findings are strictly evaluated and generated by the deterministic, version-controlled `ComplianceEngine` against codified legal rules.
- **Mandatory Human Authority**: Human officer review remains required wherever the system flags manual review, ambiguous evidence, or where statutory interpretation, physical packaging verification, or net quantity weighing is necessary.
- **Statutory Notice Protocol**: The statutory notice and memo drafting module assists officers in generating structured draft notices based on verified violations, but drafting does **not** itself constitute legal issuance or formal service. Legal issuance requires explicit officer authorization and procedural execution.

## System Capabilities

- **Inspection Workflow**: Multi-step inspection lifecycle covering inspection initiation, category selection, multi-image evidence ingestion (front, back, sides, top, bottom), automated analysis, officer review, and report finalization.
- **OCR and Evidence**: Integrated PaddleOCR and OpenCV pipeline that localizes package text regions, generates bounding boxes, calculates OCR confidence, links extracted declarations directly to image coordinates, and flags image-quality issues (such as blur/sharpness, glare, or low/suboptimal resolution).
- **Compliance Engine**: Deterministic rules engine supporting category-specific rule filtering, threshold evaluations, declaration completeness checks, units and font-size minimums verification, and explicit violation categorizations (Compliant, Non-Compliant, or Manual Review).
- **Human Review**: Interactive inspector review interface allowing authorized officers to confirm or reject detected findings, edit extracted declaration values, record inspection notes, and exercise discretionary review.
- **Reports and Statutory Notices**: Automated PDF report generation containing inspection summaries, evidence crops, and rule citations, alongside a statutory notice drafting service that generates structured violation notices and inspection memos for officer sign-off.
- **Analytics and History**: Enforcement dashboard with Key Performance Indicators (KPIs), violation category breakdowns, compliance trends, and a searchable/filterable historical inspection archive.
- **Consumer Mode**: Dedicated, simplified consumer scan interface providing public transparency by displaying basic product information and declaration summaries without exposing internal enforcement records.
- **Inspection Assistant**: Evidence-grounded side-panel assistant designed to explain specific findings, summarize inspections, explain applicable rules, and highlight items requiring manual review without altering compliance decisions.
- **Authentication and RBAC**: Secure authentication system supporting JWT sessions, bcrypt password hashing, login brute-force throttling, and role-based permissions across roles including `LEGAL_METROLOGY_INSPECTOR`, `SUPERVISING_OFFICER`, `ADMIN`, and `REVIEWER`.

## Legal & Statutory Disclaimer

PRAMAN AI is an inspection-assistance system designed to assist Legal Metrology officers in examining packaged commodities and detecting potential non-compliance. PRAMAN AI does **not** replace statutory interpretation, official gazette notifications, physical laboratory verification, or the sovereign judgment, discretion, and authority of designated Legal Metrology inspectors and controllers.

## Environment Configuration

1. Create a `.env` file in the repository root based on `.env.example`:
   ```bash
   cp .env.example .env
   ```
2. Configure environment variables as needed for your execution context:
   - **Docker Compose Context**: The backend container accesses PostgreSQL using the container service name (`DATABASE_URL=postgresql+psycopg://postgres:postgres@db:5432/praman`).
   - **Local Backend Context**: When running the backend directly on the host machine, configure `DATABASE_URL` with your local PostgreSQL connection settings (`DATABASE_URL=postgresql+psycopg://postgres:postgres@localhost:5432/praman`).
3. **Security Notice**: Never commit actual secrets, private keys, production passwords, or JWT secrets to the repository. The root `.gitignore` excludes `.env` files while tracking `.env.example`.

## Setup Instructions

### 1. Docker Compose (Recommended)

Ensure Docker and Docker Compose are installed and running:

```bash
docker compose up --build
```

- Frontend interface: `http://localhost:5173`
- Backend API documentation: `http://localhost:8000/docs`
- Health check endpoints: `http://localhost:8000/health` and `http://localhost:8000/api/v1/health`

### 2. Local Backend Development

From the repository root:

```bash
cd backend
python -m venv .venv
# Activate the virtual environment:
# Windows (PowerShell): ..\.venv\Scripts\Activate.ps1
# Linux / macOS: source ../.venv/bin/activate
pip install -r requirements.txt

# Run database migrations:
alembic upgrade head

# Start development server:
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

### 3. Local Frontend Development

From the repository root:

```bash
cd frontend
npm install
npm run dev
```

The frontend application will be available at `http://localhost:5173`.

### 4. Database Configuration

The application connects via SQLAlchemy to PostgreSQL using the connection string defined in `DATABASE_URL`. Ensure the configuration matches the execution context:
- **Docker Backend**: Uses the Docker PostgreSQL service hostname (`db:5432`).
- **Local Backend**: Uses the local PostgreSQL connection configuration (`localhost:5432` or the locally accessible database host).

## Testing
